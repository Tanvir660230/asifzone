# Stock hub (Bought · Filled · Counted) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One admin page where the owner records every purchase, every bottle fill and every count, and the system keeps stock, cost, money and website availability right on its own.

**Architecture:** A thin orchestration layer over engines that already exist: direct goods receipt + supplier bill + payment + landed cost for "Bought", `quickRefill` for "Filled", `StockCount` + valued adjustments for "Counted". Attar becomes *fill-to-order*: a variant's stock is filled bottles and may go negative (ordered, not yet filled — the costing engine's deficit), and what the website sells is `max(0, stock) + makeable`, where makeable comes from the recipe and the materials left after unfilled orders. Live switches on through a one-off go-live script (materials at the 2026-10-22 count, recipes, valuation cutover, packing rules).

**Tech Stack:** Express + Prisma + Postgres (Vitest integration tests on the test DB), Next.js 15 admin (React 19, Tailwind, `components/ui/*`), shared engines in `packages/shared`.

**Spec:** `docs/STOCK_HUB.md` (written in Task 1 from the 2026-10-22 owner conversation and the audit doc "Asif Zone finance & inventory audit" §9).

## Global Constraints

- Admin copy is English (owner, 2026-10-21: "account language we understand"); Apple-style, light only; every view handles loading, empty and error and works at 375 px; tokens/primitives only (`docs/DESIGN_SYSTEM.md`).
- A shared change ships to both installations: Nasihamart has no fill-to-order product and no materials, so its behaviour must not change (default `fillToOrder = false`).
- One writer per thing: stock only through `inventory.service`; valuation only through `costing.service`; journals only through posting rules / `journal.service`. No new direct `productVariant.stock` writes.
- Stock-moving documents need costing active (decision D-P1). The hub explains this instead of failing silently.
- Every write endpoint is idempotent by an `Idempotency-Key` header (the existing pattern) and permission-checked; new routes are added to the authorization matrix test.
- Counts and reasons: a count difference is booked as DAMAGED / LOST (loss) or ADJUSTMENT (found / count fix) at the running average. Nothing is ever typed over.
- Today's owner facts used by the go-live script (chat 2026-10-22): oil Azhaar 650 ml @ ৳38, Royal 1,352 ml @ ৳16, Sweet 250 ml @ ৳21, Zayan 1,000 ml @ ৳24; empty bottles 6 ml 166 @ ৳50, 12 ml 209 @ ৳52; boxes 553 on 2026-10-21 14:05 BDT less attar bottles booked since, @ ৳50; stickers 4,500 − bottles filled, @ ৳2,270/4,500; black poly 210 @ ৳1.60 (every parcel); bubble poly 1 roll @ ৳2,000 (attar parcels); caps 43 @ ৳587 (575 + 12 packet, packet inside the cap cost — no cap packet rule); filled attar bottles on the shelf: 0.

### Task 2: Pure capacity engine

**Files:**
- Create: `packages/shared/src/engines/fill-capacity.ts` (+ export from `engines/index.ts`)
- Test: `apps/api/src/lib/fill-capacity-engine.test.ts` (shared has no test runner; engine tests live in apps/api/src/lib)

**Interfaces:**
- Produces:
  ```ts
  export interface RecipeLine { finishedVariantId: string; materialVariantId: string; qtyPerUnit: number; wastagePct: number }
  export function makeableUnits(input: {
    recipes: RecipeLine[];                       // approved recipe lines of every fill-to-order variant
    materialStock: Map<string, number>;          // material variantId → stock (stock units)
    filled: Map<string, number>;                 // fill-to-order variantId → stock (may be negative)
  }): Map<string, number>;                       // variantId → units that can still be filled, ≥ 0
  export function sellable(stock: number, makeable: number): number; // max(0, stock) + makeable
  ```
- Rule: free material = stock − Σ over variants with negative stock of (−stock × need per unit); need per unit = `qtyPerUnit × (1 + wastagePct/100)`; makeable(v) = min over v's lines of floor(free / need). A variant with no lines → 0.

- [ ] Tests (vitest): `one recipe` (650 ml, 6 ml/unit, 166 bottles → 108); `shared bottle` (two fragrances, plenty of oil, 10 bottles → each reads 10; the shared limit is enforced at checkout in Task 4); `unfilled orders reserve material` (stock −10 on Azhaar 6 ml → free oil 590 → 98); `wastage rounds down` (3% on 6 ml → 6.18/unit); `no recipe → 0`; `sellable(−4, 7) = 7`, `sellable(3, 5) = 8`.
- [ ] Run `pnpm --filter @clothing-brand/shared test fill-capacity` → FAIL, implement, → PASS.
- [ ] Commit `feat(stock): makeable units from recipes and materials`.
